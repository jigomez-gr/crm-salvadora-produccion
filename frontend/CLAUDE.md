# Frontend — guide for Claude / AI agents (Next.js App Router)

Next.js 16 (App Router) + React 19 + Tailwind v4. Talks to the backend API over HTTP.
See the root `CLAUDE.md` for the big picture.

## Commands

> **Use `pnpm` only — never `npm`/`npx`** (see root `CLAUDE.md`).

- `pnpm dev` → http://localhost:3000 (needs `.env.local` with `NEXT_PUBLIC_API_URL`)
- `pnpm build` · `pnpm lint`

## Layout (`src/`)

- `app/` — routes: `/login`, `/` (dashboard), `/contacts` + `/contacts/[id]`, `/pipeline` (lead pipeline Kanban — all users), `/calendar`, `/conversations`, `/agents` + `/agents/[agentKey]`, `/reports` (analytics — all users), `/users` (admin-only), `/audit` (admin-only audit trail), `/settings` (admin-only white-label branding + "vaciar datos de demostración").
- `app/page.tsx` — **Inicio**, an **action panel** (ADR 0025): quick actions, a "Necesita tu atención" queue, clickable KPI tiles (`components/ui/StatCard`), "Agenda de hoy" (`GET /api/appointments/today`), clickable recent conversations (`?limit=8` → open the thread), and a pipeline mini-funnel (`GET /api/contacts/board/summary`). Everything is deep-linked; all of it refreshes live on the existing SSE events.
- `app/reports/page.tsx` — **Informes** (ADR 0020, extended ADR 0025): presets **7/30/90 + custom range** (persisted in `localStorage`) → `GET /api/reports/summary?from&to`, **trended clickable KPIs**, a conversion **funnel** (hero), citas/día with **clickable bars** (drill to `/calendar?date=…`), a **donut** of contact status, top services, capture **sources**, an auto-hiding **revenue** card, messages/día demoted to a **sparkline**, and a client-side **CSV export**. All charts are the **hand-rolled SVG/Tailwind** primitives in `components/charts/` (`StackedBars`/`Funnel`/`Donut`/`HBars`/`Sparkline`/`TrendPill`/`ChartCard` — no chart library). Read-only, any operator.
- `components/` — `Sidebar`, `AuthGate` (client route guard) + `ui/` primitives (`Button`, `Input`, `Modal`, `Textarea`, `Badge`). **Responsive shell (ADR 0021):** `AuthGate` renders a mobile top bar (hamburger) and `Sidebar` is an **off-canvas drawer** on mobile (`fixed -translate-x-full` + backdrop, closes on nav/backdrop/Escape) → a **static `w-60` column from `md` up**. **`ui/Modal` is an accessible dialog** (`role="dialog"`/`aria-modal`/`aria-labelledby`, focus trap + restore, `aria-label` close) — every modal inherits this. `lib/color.ts` `readableTextColor()` gives the brand-mark a contrast-safe foreground.
- `contexts/AuthContext.tsx` — session state (`user`, `login`, `logout`, `refresh`); restores the session from the httpOnly cookie via `GET /api/auth/me`.
- `contexts/BrandingContext.tsx` — white-label branding (`businessName`/`brandColor`/`logoUrl`), fetched from the **public** `GET /api/settings/branding` so it renders pre-auth (login). Applied in the `Sidebar` + `login` (logo mark + name) and keeps the tab title in sync. `useBranding().refresh()` re-fetches after the admin saves Ajustes or finishes onboarding.
- `components/OnboardingWizard.tsx` — first-run setup overlay rendered by `AuthGate` for admins; it self-checks `GET /api/settings` and shows only while `onboardingCompleted` is false. Collects the business name + a vertical preset (`GET /api/settings/presets`) → `POST /api/settings/onboarding`; "Omitir" just sets `onboardingCompleted`. Renders `null` otherwise.
- `contexts/ToastContext.tsx` — app-wide notifications (`useToast().success/error/info`); `ToastProvider` wraps everything in `app/layout.tsx`. Use it to surface API results instead of swallowing them.
- `app/error.tsx` + `app/global-error.tsx` + `app/not-found.tsx` — error boundaries / 404 so a render error shows a recoverable screen, not a blank page.
- `lib/` — `api.ts` (`apiFetch` with `credentials:'include'`, `apiUrl`, `ApiError`), `types.ts` (types mirroring backend contracts), `password.ts` (shared strong-password rules), `utils.ts` (`cn`).
- `hooks/useEvents.ts` — SSE subscription (`message.received`, `message.sent`, `message.status`, `conversation.updated`, `appointment.created`, `contact.updated`); `EventSource` is opened with `withCredentials` so the auth cookie authenticates the stream. Adding an event means adding it here **and** in the backend `events.controller.ts`.

## Conventions

- Pages are **client components** (`"use client"`); data is fetched client-side via `apiFetch<T>(path, opts)` from `lib/api.ts`. No server-side data fetching, no API routes.
- **Pattern:** fetch full state on load, then re-fetch on SSE events via `useEvents` — SSE only carries "something changed", the page re-pulls state.
- Keep shared types in `lib/types.ts` in sync with backend responses.
- Styling: Tailwind + `cn()` (clsx + tailwind-merge). Reuse the `components/ui` primitives instead of hand-rolling.
- **All UI copy in Spanish**; code/identifiers in English. Format dates with `date-fns` + the `es` locale.

## Gotchas

- `NEXT_PUBLIC_API_URL` is baked at **build** time, not runtime. Default `http://localhost:3001`.
- `output: 'standalone'` in `next.config.ts` (for the Docker image) only affects `next build`, not `next dev`.
- **Agent secrets are write-only.** The API never returns `openrouterApiKey`/`ycloudApiKey`/`ycloudWebhookSecret`; it returns `has*` booleans instead (`types.ts`). The config form sends a secret only to **change** it — leave a field blank to keep the stored value (the backend ignores empty secrets). Never assume `agent.openrouterApiKey` has a value. The reusable **`SecretInput`** (`components/ui/SecretInput.tsx`, shared by the agent config and the email SMTP config) makes this legible: when `has*` is true it renders a masked **"Configurada ✓"** row with a "Cambiar" button (editing sends the new value; leaving it shows/keeps the stored secret) rather than a blank box — so the operator can tell which secrets are set. After a successful save, `handleSave` refreshes the `has*` flags from the response, clears the plaintext, and bumps `savedTick` (a `key` on each `SecretInput`) so a just-changed secret re-masks.
- **Model picker is a searchable combobox** (`ModelPicker`, same file): type-to-filter over the OpenRouter catalogue (`GET /api/agents/models`), recommended models first (⭐) then the rest, with keyboard nav and per-model context/price metadata. Falls back to a free-text model-id field if the catalogue can't be loaded.
- **`suppressHydrationWarning` on `<html>`/`<body>`** in `app/layout.tsx` is intentional: browser extensions inject attributes (e.g. `data-atm-ext-installed`) before hydration. Keep it; it only suppresses attribute diffs on those two elements.
- **Auth.** `app/layout.tsx` wraps the app in `AuthProvider` + `AuthGate`: unauthenticated users are redirected to `/login` (rendered full-screen, no sidebar), and `/users` is admin-only (the sidebar link and the page both check `user.role`; the API enforces it too). `apiFetch` sends the cookie via `credentials:'include'` and throws `ApiError` (with `.status`) on non-2xx. This routing is UX only — the API is the real security boundary.
- **Password change & forced reset.** `useAuth().changePassword(current, next)` calls `POST /api/auth/change-password` (the backend re-issues the cookie). The shared `ChangePasswordForm` is used in two places: a **voluntary** modal from the sidebar (`KeyRound` → "Cambiar contraseña"), and a **mandatory** full-screen `ForcePasswordChange` that `AuthGate` renders whenever `user.mustChangePassword` is set (admin reset / first login on a temporary or default password) — there's no sidebar and no way past it. `SessionUser` carries `mustChangePassword` (from `/api/auth/me` + login); the backend independently blocks every other route (403 `PASSWORD_CHANGE_REQUIRED`) for such a user, so this isn't only UX. The Users edit form warns that setting a password forces the target to change it at next login.
- **Conversations inbox** (`app/conversations/page.tsx`): the thread list shows **unread badges** (`unreadCount`); opening a thread clears it (`POST …/read`, also optimistic locally). WhatsApp threads add a **manual composer** (`POST …/messages`) and a **handoff toggle** (`PATCH …/handoff`) — while handoff is on, the agent stops auto-replying and a banner makes that explicit. Outbound WhatsApp bubbles render **delivery-status ticks** (`queued`→clock, `sent`→✓, `delivered`→✓✓, `read`→blue ✓✓, `failed`→warning). Playground threads have no composer/handoff/ticks (no delivery). Errors surface via `useToast()`. The thread list is **server-paginated** (ADR 0019): it fetches a `ConversationPage` (`/api/conversations?limit=30&offset=…`), shows a compact Anterior/Siguiente pager, and the SSE refresh re-pulls **only the current page** (the loader closes over `offset`) — not the whole list. The dashboard's "recent conversations" uses the same endpoint (`?limit=10`, reading `.items`). **On mobile** (ADR 0021) it's a list/detail view: the thread list is full-width until a thread is opened, then the message pane takes over (with a back button); side-by-side from `md` up (driven by the `selected` state).
- **Inbound media** (`MediaAttachment` in `app/conversations/page.tsx`): a message with `mediaType` renders its attachment (image/sticker → `<img>`, audio → `<audio>`, video → `<video>`, document → download link). The bytes come from the **authenticated proxy** `GET /api/conversations/media/:id` — fetched with `fetch(apiUrl(...), {credentials:'include'})` (so the cookie is sent cross-origin, which a bare `<img src>` can't) and turned into a **blob object-URL** (revoked on unmount). The server never returns the raw media URL. The bare emoji placeholder (`📷 Imagen`, …) is hidden once the media renders (`MEDIA_PLACEHOLDERS`, mirrors `inbound-parser.ts`), but a real caption/filename stays.
- **Contacts** (`app/contacts/page.tsx` + `[id]`): contacts carry a `status` (lead/active/inactive), `tags`, `source` and `customFields` — the form edits them all (tags as a comma string, custom fields as key/value rows), the list shows a status badge + tags + a status filter, and the detail page renders them. `lib/contacts.ts` holds the shared status label/Badge-variant map. The list is **server-paginated** (ADR 0019): it fetches a `ContactPage` (`{items,total,limit,offset}`) and sends the **search** (debounced 300 ms) + **status** as query params — both filter server-side now (no client-side `.filter`) — with an Anterior/Siguiente + "X–Y de N" pager (mirrors `app/audit/page.tsx`); changing a filter resets to page 1. **CSV**: "Exportar" fetches `/api/contacts/export` with `credentials:'include'` → blob download; "Importar" reads the file via `FileReader` and posts `{csv}` to `/api/contacts/import`, then shows the `{created,updated,skipped,errors}` summary. The detail page also has **consent/GDPR** actions: a "Dar de baja"/"Reactivar" toggle (`POST …/consent`) and "Anonimizar" (`POST …/anonymize`, confirm modal); opted-out contacts show a "Baja" chip in the list + a badge on the detail page.
- **Reminders config** (`app/agents/[agentKey]/page.tsx`): the agent config form has a "Recordatorios de cita" card — a toggle (`remindersEnabled`) + the HSM template name/language. Like every other field it's part of the `form` state and round-trips through the single `PUT …/config` save (the API returns these — they're not secrets).
- **Agent behaviour + knowledge base** (`app/agents/[agentKey]/page.tsx`, ADR 0022): the config form clarifies **"Descripción del negocio"** (*what the business is*) and adds **"Comportamiento del agente"** (`customInstructions` — *how it should act*; round-trips through the single `PUT …/config` like the other fields). The **"Base de conocimiento" card** (`KnowledgeCard`) manages its **own** endpoints (`GET/POST/DELETE /api/agents/:agentKey/knowledge`), **not** the config `PUT`: upload a file (read via `FileReader.readAsDataURL` → posted as `{filename, contentBase64}` JSON through `apiFetch` — no multipart/`FormData` needed since it's base64), a document list with per-row delete (confirm `Modal`), and a budget/mode indicator (`inject` = whole base each message / `retrieve` = relevant fragments). Formats: TXT/MD/CSV/PDF/DOCX/XLSX, ≤ 4 MB. Errors (e.g. a scanned PDF with no text) surface via `useToast()`. Its buttons are `type="button"` so they don't submit the surrounding config `<form>`.

- **Business email / SMTP** (ADR 0024): **Ajustes → "Correo electrónico"** card (`EmailCard` in `app/settings/page.tsx`, admin) configures the account — a **provider preset** selector (Gmail/Outlook/Otro) auto-fills host/port/TLS with guided help + links, the shared `SecretInput` for the password, and an **"Enviar prueba"** button (`POST /api/email/test`). Config round-trips through `GET/PUT /api/email/config` (sanitized — `hasSmtpPassword`, never the password). The **contact detail page** (`app/contacts/[id]/page.tsx`) has an **"Enviar correo"** button (disabled with a reason if the contact has no email or `GET /api/email/status` says unconfigured) → a compose modal (`POST /api/email/send`), plus a **"Correos enviados"** history (`GET /api/email/contact/:id`). Sending is any operator; config is admin-only.
- **Drill-through deep links** (ADR 0025): the dashboard/reports link into filtered screens, so the target pages read query params — contacts (`?status`/`?new`/`?search`), conversations (`?thread`), calendar (`?date`/`?new`). `useSearchParams()` **must** sit under a `<Suspense>` boundary (App Router) — each of those pages is split into a `…Inner` component (which reads the params via **lazy `useState` initializers**, never a synchronous `setState` in an effect — React 19 forbids it) wrapped by a thin default export in `<Suspense>`. A param that isn't recognised degrades to the bare route. The calendar appointment form also has an optional **"Precio (€)"** input (empty → omit on create / `null` on edit).
- **Charts + KPI tiles** live in `components/charts/` (`ChartCard`, `StackedBars` with optional clickable bars, `Funnel`, `Donut`, `HBars`, `Sparkline`, `TrendPill`) and `components/ui/StatCard`. All are dependency-light **accessible SVG** (`role="img"`/`aria-label`, real `<button>`/`<Link>` for clickable segments, colour never the only signal). `lib/reports.ts` (`FUNNEL_LABELS`/`FUNNEL_COLORS`, `formatPercent`/`formatEuro`, `trendDisplay` — outcome-semantics + low-n neutralisation) and `lib/appointments.ts` (status meta) back them. Keep the no-chart-library rule (ADR 0025).
- **Lead pipeline / Kanban** (`app/pipeline/page.tsx`, ADR 0023): a drag-and-drop board of the six funnel stages (`lib/pipeline.ts` holds the stage order + Spanish labels/colours + `positionBetween`). Fetches `GET /api/contacts/board` (`BoardData` — contacts grouped by stage, each card enriched with `nextAppointment`). Drag uses **`@dnd-kit`** (`core`/`sortable`/`utilities`) with `PointerSensor` (5px activation so a click still opens the contact) + `KeyboardSensor`. Moves are **optimistic**: a `columnsRef` mirrors state so drag handlers read the latest board without stale closures; cross-column placement is finalised in `onDragOver` and only pure same-column reorders `arrayMove` in `onDragEnd` (else the card lands one slot off — track the origin stage). Persist = `PATCH /api/contacts/:id` `{ pipelineStage, boardPosition }` (a midpoint between neighbours), reverting via refetch on error. Live via `useEvents({ "contact.updated", "appointment.created" })` — but the refetch is **skipped mid-drag** (`activeIdRef` guard) so it never yanks a card. The board is its own sidebar entry ("Embudo", `KanbanSquare`), visible to all operators.
